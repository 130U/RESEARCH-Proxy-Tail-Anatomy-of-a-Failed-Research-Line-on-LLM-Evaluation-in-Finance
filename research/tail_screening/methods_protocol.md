# Pairwise comparison and multi-ranking aggregation: design fixed before any output

2026-11-16. Execution continues with isolated model sessions. The source and recomputability principles of Research Methodology and Research continue to apply; the sources are the position-swapped comparisons of Qin et al. (NAACL 2024), the multi-permutation aggregation of Tang et al. (NAACL 2024), and the locally saved data and actual agent outputs. Existing knowledge is enough to design the measurement, but the stability of the two methods on the current financial texts is unknown. This round's question is "can a sufficiently stable finite-sample ranking be obtained", not proving an asymptotic tail law.

## Stage 1: 32 completely new items

After excluding all 128 families of the previous round from the old test split, 32 families were drawn with a fixed rule from the remaining 1,442 families, one item per family. Family seed=20261119, within-family seed=20261120. Items were not picked by sentiment, label or old model predictions. The two model tiers are gpt-6-luna / gpt-6-sol as set in the session runner; each session starts from an empty context and does not see another session's outputs; reasoning_effort is not explicitly overridden, and the visible underlying sampling parameters or internal version cannot be fixed.

The semantic task keeps the previous round's corrected version: the positive or negative expression, and its strength, in the financial context of the headline toward the specified entity, not actual shareholder returns. Entities that appear only as commentary sources, ordinary facts, or text with no direction toward the target can be neutral; an item is not automatically inconclusive because the entity is not a company.

**Pairwise comparison.** All 496 unordered pairs of the 32 items form two repeat panels; each panel has two inputs a/b, with left and right swapped pair by pair, and the document order and pair order shuffled independently. Each input is judged in batch by one fresh agent, so there are 4 calls per model, 8 for both models, and 3,968 judgments in total. Context is shared within a batch, so these are by no means 3,968 independent API requests or independent samples. For each pair, first convert to a common item direction; a win/loss is kept only when both runs choose the same item, other cases are recorded as ties, and the left-right swap inconsistency rate is listed separately. Each panel aggregates by (wins + 0.5×ties)/(n−1), keeping exact equalities as ties; no random perturbation is added and no probability model is fitted.

**Rank aggregation.** Each model reads 8 independent random permutations, each of which a new session turns into ordered tie groups. order1–4 form panel1 and order5–8 form panel2. Midranks are used within groups, and (n−midrank)/(n−1) is averaged with equal weights to form the Borda score. This is implemented with the integer "sum of twice the ranks", keeping true equalities and avoiding spurious floating-point resolution. The main method is four-run aggregation per panel; the prefix aggregations m=1, 2, 4 are also reported, as specified in advance, as a sensitivity display, and the best m cannot be picked after the fact. Both models together make 16 calls. Tang's specific Kemeny theory does not automatically apply to the Borda implementation here.

24 scoring calls in total. Inputs, outputs and the exact prompt are stored in research/private/agent_tail_methods/stage1_n32/. Repeated calls on the same batch of documents are not treated as more financial samples, and the errors of the two models are not assumed to be independent.

**Batching adjustment during execution (before any formal pair output):** Luna's first whole-batch task with 496 pairs returned that it could not finish and produced no file; Sol's task of the same size stopped after reading the input and also produced no output. To make the pairwise tasks completable, each panel/orientation was split into 4 fixed batches of 124 pairs, with the same split for both models and the a/b batches swapped pair by pair. The assignment seeds for the two panels are 20261201 and 20261202; each batch keeps the full 32-document context, and within-batch correlation is reported. Formal pairwise comparison is 32 calls, still 3,968 judgments, plus 16 listwise calls, for 48 formal scoring calls in total, with the 2 no-output attempts above counted separately. The statistical aggregation rules and pass conditions are unchanged; the "24 calls" in the earlier text is the first plan, and the actual calls are as stated here.

## Scale-up conditions and analysis

Every ID/pair must be covered exactly once; any inconclusive item makes that method's full-population gate fail, and a separate common-subset diagnostic cannot be turned into a pass. For each model, the two panels are compared for the upper and lower tails and in both directions. The main working thresholds for stage 1 are at p=25% (nominal 8 items): equal-budget recall≥80%, q/p≤1.5 for 90% recall, and boundary-tie expansion at both ends ≤20%. p=12.5% (4 items) is only a small-tail diagnostic, and alpha is not fitted. These are pre-specified working thresholds, not calibrated significance tests.

All lists keep the complete boundary ties, and the nominal count, actual count, q, q/p and equal-budget overlap are reported. The outputs also include the ranges over all four cross-model combinations of the two panels, same-model repeats and midrank correlations; the ranges are not confidence intervals. The pairwise route additionally reports the strict swap inconsistency rate, the merged tie fraction and strict three-edge cycles, keeping the graph rather than forcing a pretense of transitivity.

A method is scaled up only after both models pass the stage 1 working thresholds. If both routes pass, the four-run ranking aggregation, which needs fewer individual judgments, is validated first; the pairwise route is kept as a reviewable comparison. For the aggregation route the next stage is 128 new families (excluding all earlier samples), still with 2 panels×4 runs×2 models, with the main thresholds changed to p=10%, 20% and the other stability criteria unchanged; after a pass it can be scaled up to 512 new items, and whether there are enough tail samples at that point will be reported separately. If the pairwise route becomes the only passing method, it is first scaled up to 64 new items for a full comparison; the full comparison grows as n², so the number of judgments must be reported, and a sparse approximation that was not run cannot substitute for it.

If both fail stage 1, the sample is not scaled up and the original tail hypothesis is not declared wrong: report the failure mechanisms of the two specific methods, the unmet items and the theoretical limits. If a method fails on a new sample, the complete failure results are kept, and one cannot keep tuning on the same validation set and still call it validation. After all routes have produced results, compile this round's stage report, the final figures, the raw record paths, the recomputation scripts, the theory/literature links and a clear assessment.

## Single-model validation branch added after stage 1 (before stage 2 output)

Stage 1 completed 48 formal scoring calls, 3968 pair judgments and 16 listwise rankings: both models failed with the pairwise method; with four-run Borda aggregation, Sol passed as a single model and Luna failed. So the joint two-model plan stays FAIL, and **the original two-model scale-up condition is not changed to a pass**.

I then decided to "scale up the method that passed". Accordingly, a separate stability validation of the selected single model was set up: only for the passing Sol + four-run aggregation per panel, run on 128 completely new families with two panels, 8 new sessions in total. The original 128 families and all 32 stage 1 families are excluded; family seed=20261216, within-family seed=20261217; the seeds for the 8 input permutations are 20261218–20261225. The input IDs are V0001..V0128; the semantic prompt is unchanged, and human labels/old predictions are not read.

This branch is a candidate selected after observing stage 1 and then validated on new data; it cannot be called a pre-specified success of the original two-model protocol. On the new data, the main p is fixed in advance at 10% and 20%; for the same model, both directions and both tails require equal-budget recall≥80%, q90/p≤1.5 and tie expansion≤20%; m=4 decides, m=1/2 are sensitivity results reserved in advance, and 5% is only a small-tail diagnostic. Repeats of the same text are not treated as independent samples. If this single-model validation fails, it is not tuned on the same validation set and relabeled a success; if it passes, the scale change can then be tested on 512 new, unused families. In any case, the failed Luna branch does not follow in scaling up, and Sol being stable does not mean objective truth, nor that a full cheap/expensive model study has been established.
