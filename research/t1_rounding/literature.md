# T1 prior-art check: input rounding precision and answer determinacy in financial QA

Search date: 2026-11-16 (America/New_York; some accesses have the UTC date 11-17). This is a focused first screen done in parallel; it does not claim an exhaustive search over half a day of wall-clock time. No model scoring, no model training and no paid APIs were used.

## Verdict

**This round found no direct duplicate of "the same question with the same measurement", and the task's stopping condition for a matching study has not been triggered.** "Direct duplicate" here means: in FinQA, TAT-QA or a similar existing financial QA benchmark, building feasible intervals from the reported precision of the document's input numbers, propagating them through the gold program, and counting the fraction of questions whose possible answers cross the scoring acceptance region. The search found no work that covers all of these steps together; this is not proof that "no one has done it before".

**We can continue a benchmark audit with explicit thresholds, but we cannot present interval arithmetic itself, the uncertainty of financial rounding, or the handling of duplicate facts at different precisions as new mathematical theory.** Each of these components has clear prior work. If the end result is only moving an existing method onto one dataset, the research contribution may be insufficient; the remaining value lies in reviewable frequencies, the concentrated risk of nonlinear operations, and testable predictions about changes in quantified precision.

This further rules out describing the contribution as "first to notice that text and tables have different precision".

## Verification of the official scoring rules

The original FinQA paper's goal is to answer numerical reasoning questions from filings, and it releases expert-written gold reasoning programs. [Original paper and project entry](https://aclanthology.org/2021.emnlp-main.300/)

The FinQA repository `main` checked here points to `0f16e2867befa6840783e58be38c9efb9229d742`. The official `eval_program` applies `round(..., 5)` to the numeric result after the operations finish; `evaluate_result` compares that result directly with `qa.exe_ans`, and there is a separate symbolic program-equivalence score. **The official program execution accuracy is not a "1% relative tolerance", nor "rounding to the displayed digits of the qa.answer string".** So T1's two rule sets should be called "preset audit tolerances" and listed separately from the official execution rule. [Pinned-version evaluator](https://github.com/czyssrs/FinQA/blob/0f16e2867befa6840783e58be38c9efb9229d742/code/evaluate/evaluate.py)

TAT-QA's official `get_answer_str` first applies `round(ans_num, 2)` to ordinary numbers, multiplies by scale, and then formats to four digits; strings containing `%` go through a different normalization branch. For arithmetic questions F1 equals EM. It is also not simple rounding to the last digit of the original gold string. So if the work is extended to TAT-QA, the distinctions among percentages, scale and the official normalization must be kept. [Official scorer](https://github.com/NExTplusplus/TAT-QA/blob/master/tatqa_metric.py); [original paper](https://aclanthology.org/2021.acl-long.254/)

1% was not made up: for example, the documentation of OpenEnv's FinQA environment states that it uses a 1% relative or 0.01 absolute tolerance. But that is a 290-question environment based on Snorkel AI's FinQABenchmark, and **it cannot be used to prove that the official scoring of the original FinQA is 1%**. [OpenEnv official environment documentation](https://huggingface.co/docs/openenv/v0.4.2/environments/finqa)

## Constraints on this measurement

The following are research-design judgments drawn from the sources above; they are not T1 results that these papers have already reported.

1. **The object of study must be stated precisely.** With the document's displayed numbers as arithmetic inputs, the benchmark answer may be fully determined; only when the displayed numbers are read as constraints on latent unrounded facts can the function value of the true quantities cross the tolerance. The latter does not automatically prove that the benchmark is mislabeled or that a model cannot complete the original task.
2. **"Outer-interval out of tolerance" is only a candidate.** Ordinary interval arithmetic can be too wide when the same operand is used more than once. To claim that several legitimate latent answers really exist, one should give a feasible input witness, or use an exact range or a certified bound; a loose outer bound that leaves the tolerance cannot by itself be counted in the proven fraction.
3. **Precision should be traced to the location of occurrence and to the identity of the quantity.** Amounts, ratios, unit-conversion constants, years and counts cannot all be given a half-unit error; the same value is not the same financial fact. Only duplicates with the same entity, same definition, same period and same unit are suitable for merged constraints.
4. **Use the document evidence fully.** When the same fact appears in several places, plugging in the different displayed values separately measures "sensitivity of the computation to its source"; but a claim that the whole document is still indeterminate should merge this evidence. Known financial identities can also shrink the feasible set. A fraction computed on separate input boxes must state the information set used.
5. **Units are not the same as information precision.** Writing 12 million as 12,000 thousand adds no information. Only extra significant digits that actually provide thousand-level precision correspond to the counterfactual of a narrower interval; without more precise real data, we cannot say the effect of rewriting the reporting unit has been empirically verified.

## Research positioning that can be submitted

Suggested framing: **a reviewable audit of the input-quantization sensitivity of reference computations in financial QA, under fixed question semantics, evidence set and rounding model, testing which operation types and reporting precisions cause latent results to cross a preset acceptance region.**

It should not be framed as "discovering a new interval theory", "the first discovery that filings have rounding errors", "proving that FinQA's reference answers are wrong", or "having proven that no literature on the same question exists". If a later search finds the same question and measurement, expansion should stop the same day under the task rules, keeping the evidence and an explanation.
