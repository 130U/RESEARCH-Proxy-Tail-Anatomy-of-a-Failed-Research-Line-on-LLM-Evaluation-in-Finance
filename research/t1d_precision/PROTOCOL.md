# T1D execution conventions

The original task text is `TASK.md`, fixed on 2026-11-17 before the formal B/C answering. Prompts are extracted verbatim from that file; C only inserts the teaching paragraph as the original text specifies. We reuse T1C's frozen 392 questions and their full document texts: no resampling, no retries based on correctness, and format errors are kept.

- The main model is `gpt-6-astra` at `ultra` reasoning effort. Each prompt starts an independent ephemeral session with shell, browser, plugins, apps, other agents, and memory disabled; the working directory is an empty `.runtime`. Actual session events and whether tools were called are recorded; no paid API is used. The exact service version of the previous round's A was not exposed, so a service-condition comparability limitation remains between A and the new conditions.
- B/C are planned at 392 calls each. The full B required by the task is completed first, then C; at most three reasoning sessions run at once, keeping the priority service tier in the current user configuration. C runs the fixed half sample first and then fills in the remaining questions; only if the call budget runs short is the task-permitted fixed C half sample used, drawing 98 pairs (196 questions) with seed 20261117 after sorting by pair_id. Whether the half sample is used will be recorded explicitly, and extra answers already returned are still kept. Ten questions are drawn from the training set only to check format and the run procedure; none of these trial questions are among the formal 392. B/C run at different times, so changes in time slot or service are a comparability limitation.
- The numbers in each answer are bound to the source facts they use, and a half-last-digit-unit box is built from the source's displayed unit; the same fact shares one variable, and counts, years, dates, and contract terms are treated as exact, as the prompt states. Source bindings with an explicit unit conversion are allowed but keep their ratio; when a number's identity cannot be confirmed it is excluded with an explanation, and the gold answer is not used to choose a binding. A was not asked to write numbers as displayed, so an explicit pre-converted number cannot automatically be treated as an exact constant.
- The truth value is computed with rational numbers on the model's own formula. A corner range is called exact only when monotonicity or a coordinate-wise linear-fractional property is proved; cases that cannot be certified are listed separately. Zero centers and zero widths are listed separately. d* uses `log10(abs(c)/((U*-L*)/2))`; it is not changed to a first-order or maximum relative radius.
- We follow TASK.md strictly for: the width ratio [0.5,2], an envelope tolerance of 5% of the true width at each end, a digit error of ±1 and over-reporting >1, the 1% maximum radius, and the definition of self-contradiction. A has only literally printed digits; the figures state explicitly that this is not equivalent to the reliable digits B/C self-report.
- The "12 to 16 printed digits" in the background comes from T1C `research/t1c_models/ONE_PAGE.md:22`: in the subset of growth questions with the same source and the same formula, witness 69 questions / control 75 questions, the median printed digits are 16/12 respectively; the filter is in that round's `analyze.py:129–138`. This is not a statistic over all 392 questions. This round counts A's literal significant digits from the raw `answer` string (keeping trailing zeros); the median over all 391 numeric answers and over the 378 scorable answers is 5 in both cases. The difference comes from the denominator and the mix of question types; no metric or data was changed because of it.
- Report both all scorable answers and the subset consistent with the official formula; then break down by original group/operation. Each item gets a 95% interval from 10,000 page-cluster bootstrap draws, seed 20261117; the original page definition of 237 clusters is kept, and all subsets share fixed 237-cluster resampling weights. C−B uses only the same question under the same subset convention, resampled as page-clustered pairs. The first-order-gradient baseline and the always-certain baseline are each compared on the same available answers for that metric; when the B/C formulas differ, baselines are reported separately.
- The three-way conclusion follows TASK.md's 80%/90% thresholds directly; if any condition has more than 10% unscorable, the reasons are reported first, missing values are not counted as successes, and a favorable subset is not used to avoid the exception.
- T1B round two covers the 196 witnesses + 60 fixed with seed 20261117 from all the original stable questions; shuffled and anonymized, the reviewer sees only doc/question/reference program/input provenance. T1C round two covers the 68 rejected expressions, following the original rubric; the anonymized material contains no old judgment, group, or interval. A different tier, `gpt-6.1-sol`, `high`, is used where possible. Round three uses fresh sessions that see only the two reasons in random order plus the original material, without round labels; all three labels are kept.
- Round-two semantic material is handed, in the frozen anonymized order, 16 questions at a time to a brand-new session; round three uses batches of at most 8 questions; no judgment or history passes between batches. The raw JSON array of each batch is kept in full; per-question files only cut out their original object and note the shared session source, without claiming that every review item is a single-question session. B/C answering still uses a strictly new session per question. Round three uses `gpt-6-astra`, `ultra`; the display copy of each reason only removes explicit process-source prefixes, and the raw reasons and the transformation record are kept.
- The main retention count is the strict intersection of the 196 witnesses judged valid in both rounds; the round-three majority result is listed separately. The 60 controls have no first-round semantic label and are not mixed into the denominator of the two-round agreement rate. The main attribution comparison uses T1C's final saved old attributions; the raw old records are read-only.

This round delivers one figure with three panels, a one-page summary, results.json, per_response.csv, raw answers/prompts, and the scoring and analysis code. The short paper would be written after a per-question recomputation. This run does not extend to training, paid APIs, other benchmarks, or the full text of the original annual reports.

Optional rerun: after the main experiment and the necessary blind review are complete, if the call channel/quota allows, rerun B in full on the same 392 questions with `gpt-6.1-sol`, `high`, in a directory marked `B_secondary`. Its prompt reuses B verbatim, and the results are listed separately in `results.secondary_B`; they are not mixed into the main model's A/B/C table, paired differences, figures, or three-way classification. If it cannot be completed, the actual scope and reason are reported, and partial results are not called a complete rerun.

After all the necessary semantic reviews were complete, the other model-tier channel was confirmed available and the full 392-question `B_secondary` started. To use the waiting time of main condition C, this item was moved earlier to run in parallel with C; the planned model, effort, verbatim B prompt, and separate analysis convention are all kept. After sorting by question number, the questions are split by index mod 3 into three non-overlapping scheduling shards, and the first shard runs in the fourth slot first; after C finishes, the remaining shards can run in the freed slots. Shards are used only for scheduling, not as a sampling or exclusion condition.
