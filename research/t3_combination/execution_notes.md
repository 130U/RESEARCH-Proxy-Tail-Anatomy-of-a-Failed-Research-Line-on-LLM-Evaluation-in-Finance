This revision is a design problem found during execution. The conclusion is positioned as an exploratory one-day screen; it cannot be claimed as a strictly unmodified confirmatory experiment. The total call count should include the first version's 4 calls; the formal analysis plan remains 88 calls and 3360 scores.

The numerical environment is Python 3.12.14, NumPy 2.5.3, SciPy 1.18.1, Matplotlib 3.11.2, consistent with the repository's requirements-analysis.txt. Locally available dependencies were used; no new model API or training was added. Before reading the full main scores, the analysis code ran synthetic checks of the hand-calculated formulas and parameter recovery; these synthetic numbers ran only in memory and were not written to any scoring file. Input checks confirmed that the prompt is verbatim identical, that there is no design-polarity field, that each pair has both orders, the specified number of repeats for each item, and the mapping of input texts.

Recomputation: in a Python environment with the dependencies listed in requirements-analysis.txt installed, run `python research/t3_combination/analyze.py` from the repository root. This command only reads the existing raw outputs and schedule; after verifying that the 88 calls / 3360 scores are complete, it regenerates scores.csv, results.json, report.md and combination.png/pdf, without calling the scoring model. `--self-test` only runs the synthetic numerical checks. prepare.py only builds the material and refuses to overwrite existing main scores; it cannot be used to recompute the statistical results.
